# 第39章　做一个能输入的七字母练习字体

前面的四字标题设计，把轮廓放在一起就能看效果；但一组画好的字，还不能自动成为可输入的字体。这次把范围缩小到能做完的一件事：做一款名为 **PracticeGrid Atlas** 的原创模块字体，覆盖大写 A、E、H、I、L、O、T 和空格。输入 `HELLO` 或 `A LITTLE`，软件就能从字体文件中调用对应轮廓。我们不靠扩大字符数量展示完成度，而是走通“画字—指定字符—设置空间—导出—输入测试”的过程。

![原创PracticeGrid Atlas的模块网格、真实排印与字体度量](../assets/images/fig-39.png)

*图39｜原创七字母静态字体练习。样张来自随书提供的真实 TTF，而非把字母图片依次摆放；模块网格和度量线帮助读者检查形状与占位。它不是中文字体，也不覆盖完整拉丁字母表。*

## 先拿到可以检查的成品

下载[练习字体 TTF](../assets/designs/practice-font-Regular.ttf)、[可编辑网格 JSON](../assets/designs/practice-font-grid.json)与[使用说明](../assets/designs/practice-font-README.md)。可以先用系统字体预览器查看，不必立刻安装。若要在排版软件中输入，安装时确认字体族名为 PracticeGrid Atlas，重新打开需要的应用，再选择这个字体族。练习不需要替换系统字体；如果安装管理器提示同名字体已存在，先核对是不是自己的旧版。

新建一个文本框，关闭自动替换文案的功能，输入 `HELLO`，再另起一行输入 `A LITTLE`。这里的空格由字体自己提供；不要用若干个空格人为修正字距。随后输入 `HELLO!` 作一次边界测试：叹号不在覆盖范围内。应用可能出现缺字符号，也可能用另一款字体补上叹号。看见叹号不能证明本字体含有这个字；检查实际使用字体或字符映射，才能区分自己的轮廓与字体回退。

## 一张网格如何变成轮廓

源文件以七行、每行五个字符记录一个字形，`1` 表示实心模块，`0` 表示留白。以 H 为例，两侧竖列贯通，第4行横向连接。构建脚本把每格转换成边长100字体单位的方格，去掉相邻模块的公共边，再沿剩余边界走成封闭轮廓；因此结果是可以缩放的矢量轮廓，并不是嵌在字体里的位图。

本练习选用1000单位的 em 方框，大写顶线为700，基线为0。每个字形的黑色轮廓横跨 x=50 到550，前进宽度为600，左右各留50单位。空格没有可见轮廓，前进宽度为300。这里的数字是这份练习的统一设置，不是字体行业必须采用的唯一比例。上升与下降行度量分别为800和−200，为轮廓与连续行保留空间。

在网格里改变一个模块，改变的是黑色形状；修改前进宽度，改变的是下一字从哪里开始。两者不能混为一谈。字体的水平度量表 hmtx 记录前进宽度（advance width）与左侧边距（left side bearing），其含义可查[OpenType hmtx 说明](https://learn.microsoft.com/en-us/typography/opentype/spec/hmtx)。同样600的占位也不意味着所有字在视觉上同样均衡：L 的右侧上部留白远多于 H，所以它们仍然值得放回词里比较。

## 字符映射让轮廓响应键盘

构建器为 A 指定 U+0041，为 E 指定 U+0045，其余字母同理；空格使用 U+0020。字符映射表（cmap）将这些编码关联到字体中的字形名称。另有一个未编码的 `.notdef` 字形，作为未定义字形的基础表示。八个编码字符加上它，共九个字形；“字形总数”和“覆盖字符数”在这里已经不同。[OpenType cmap 文档](https://learn.microsoft.com/en-us/typography/opentype/spec/cmap)解释了字符到字形索引的关系。

这份练习只包含一个 Regular 样式，没有可变轴、字偶调整或连字。它采用等宽大写，是为了让读者先看清规则如何进入文件；不要把这些简化理解为完整字体开发的全部内容。加入小写、标点或中文时，既要设计新轮廓，也要处理新的度量、编码与连续阅读问题。

## 改一次，再重建一次

打开 JSON，在 E 的第4行把 `11110` 改为 `11100`，表示缩短中间横画，其他行保持原样。在工程根目录安装依赖并重建：

```bash
python -m pip install -r requirements.txt
python scripts/build_practice_font.py
```

脚本使用 fontTools 的 FontBuilder 生成字体，随后重新读取输出文件，核对八个字符映射、九个字形、600单位字宽、空格宽度、各字轮廓边界与测试文案覆盖。这些检查能发现漏编码、空轮廓和度量偏离；它们不能代替人的视觉判断。脚本还检查网格行列和内容，并拒绝会使边界追踪产生歧义的角点相触结构。构建器的实现可参阅 [fontTools 官方源码](https://github.com/fonttools/fonttools/blob/main/Lib/fontTools/fontBuilder.py)。

重建后先在预览器中检查 E，再把 `HELLO` 排成一行，看看中横缩短后是否更清楚，还是使它过于接近别的形状。试用字号既要有大标题，也要有较小的标签；缩小后模块之间的空间可能不再明显。接着重复输入 `HEHE`，检查同样的形状在连续节奏中是否显得过重。如果计划安装修订版，应同时修改构建器的字体族名、PostScript名称和版本标识，使应用能区分新旧文件；只改磁盘文件名通常不足以解决字体缓存问题。

## 留下可重复的判断依据

保存原网格、改后网格和同尺寸的前后样张，旁边写明“只缩短 E 的中横，未改字宽”。这样下一次比较时，才能知道差别来自哪里。完成一次修改以后，再尝试增加字符：先选一个确实需要的字，例如 F，而非一口气追求完整字符表。新增后要同时更新源数据、覆盖范围声明与校验逻辑，避免出现“字已画好、脚本却没把它编码进去”的半成品。
